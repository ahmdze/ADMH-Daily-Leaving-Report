# نظام موقف الإجازات اليومية — النسخة المؤسسية 2.0

نظام سطح مكتب لإدارة موقف الإجازات اليومية في المؤسسات الصحية العراقية.
يعمل **بالكامل بدون إنترنت** على حاسوب واحد: لا سيرفر، لا مزامنة، لا حساب سحابي.

---

## 1) التشغيل

افتح الملف `index.html` بالنقر المزدوج.

| المتصفح | الحالة |
|---|---|
| **Google Chrome** (105+) | الدعم الكامل — يفضّل للاستخدام الرسمي |
| **Microsoft Edge** (105+) | الدعم الكامل |
| Firefox | يعمل، لكن **بدون** الحفظ التلقائي في مجلد على القرص |

للتثبيت كأيقونة على سطح المكتب: افتح `index.html` في كروم ← قائمة المتصفح ←
«إرسال إلى ← إنشاء اختصار». يفتح النظام بعدها كنافذة مستقلة تشبه التطبيق.

---

## 2) أين تُحفظ البيانات

البيانات محفوظة في **ثلاث** طبقات، فلا تضيع إن تعطّلت إحداها:

```
الذاكرة  →  IndexedDB (داخل المتصفح)  →  مجلد على القرص
```

### ربط مجلد البيانات (موصى به بشدة)

شريط أصفر أعلى الشاشة ينبّهك حتى تربط مجلداً. اضغط **«ربط مجلد البيانات»**
واختر مجلداً (يُنصح بمجلد داخل «المستندات»). بعد الربط تُحفظ كل التعديلات
تلقائياً، وتُنشأ نسخة احتياطية يومية.

### ما يوجد داخل مجلد البيانات

```
settings.json            إعدادات الترويسة والشعار وسياسة الأيام
holidays.json            العطل الرسمية ومعاملة كل عطلة
departments.json         الأقسام والشعب
staff.json               دليل الموظفين وأرصدتهم
leave-types.json         أنواع الإجازات وألوانها
leaves/leaves-YYYY.json  سجلات الإجازات — ملف لكل سنة
leaves-index.json        فهرس سنوات السجلات
compensations.json       الأيام التعويضية المستحقة
audit.json               سجل التدقيق (من فعل ماذا ومتى)
backups/                 نسخ احتياطية كاملة — يُحتفظ بآخر 30 نسخة
*.prev.json              النسخة السابقة من كل ملف (حماية من تلف الكتابة)
```

> كلها ملفات نصية يمكن فتحها وقراءتها ونسخها على فلاشة.

### في Firefox أو بدون ربط مجلد

البيانات تبقى داخل المتصفح فقط. لذلك:
- استخدم **«تصدير نسخة احتياطية (JSON)»** دورياً واحفظ الملف خارج الجهاز.
- أو افتح النظام بـ Chrome / Edge لتشغيل الحفظ التلقائي.

> **تحذير:** تنظيف «بيانات المواقع» في المتصفح يمحو البيانات المرتبطة بالمتصفح.
> وجود مجلد مربوط يجعل ذلك غير مؤثر.

## 3) سياسة احتساب الأيام (الإعدادات ← سياسة الأيام)

النظام لا يفرض قاعدة قانونية من تلقاء نفسه، بل ينفّذ ما تقرره مؤسستك:

**العطل الرسمية داخل مدة الإجازة — نمطان:**

| النمط | مثال: إجازة 3 أيام تضم عطلة رسمية | النتيجة |
|---|---|---|
| **العطلة من ضمن الإجازة** | لا تؤثر على عدد الأيام | تُخصم **3 أيام** |
| **العطلة تُستثنى** | يُخصم أقل، ويُستحق يوم تعويضي | تُخصم **يومان** + **يوم تعويضي** على الموظف |

**خيار إضافي:** هل تُحسب أيام الجمعة والسبت من الإجازة؟ (افتراضياً: نعم تُحسب).

**تجاوز لكل عطلة:** من شاشة «العطل الرسمية» يمكن ضبط كل عطلة على حدة:
«حسب السياسة العامة» أو «داخل الإجازة» أو «تُستثنى».

**الأيام التعويضية** تُقيَّد تلقائياً في سجل رصيد لكل موظف عند استثناء عطلة،
وتظهر في شاشة الموظفين بزر «X يوم مستحق»، مع زر **تسديد** عند تعويض الموظف
اليوم في تاريخ آخر.

### العطل الرسمية
- زر **«تهيئة العطل الثابتة لسنة»** يضيف: رأس السنة، عيد الجيش، نوروز،
  عيد العمال، 14 تموز، عيد الاستقلال، يوم النصر.
- **العطل الهجرية** (الفطر، الأضحى، المولد، عاشوراء، الغدير…) متغيّرة،
  لذا تُضاف يدوياً كل سنة — زر «العطل المتحركة» يذكّرك بها.

### إعادة الاحتساب
بعد تغيير السياسة أو إضافة عطل، زر **«إعادة احتساب كل السجلات»** يحدّث الأيام
المخصومة والتعويضية لكل السجلات، ويُسجَّل في سجل التدقيق.

## 4) الميزات

- **الموقف اليومي:** يوم / شهر / فترة مخصّصة / كل السجلات، مع فلاتر القسم
  والنوع والحالة والبحث الفوري، وفرز بالنقر على أي عمود، وترقيم صفحات.
- **إدخال إجازة:** بحث تلقائي في دليل الموظفين، احتساب فوري للمدة،
  عرض العطل الواقعة داخل المدة، وكشف التداخل قبل الحفظ.
- **كشف التداخل:** نافذة تفصيلية تُظهر التعارضات والأيام المتداخلة، مع خيارات
  (تعديل التواريخ / إلغاء الحفظ / الحفظ مع تجاوز بسبب يُسجَّل في التدقيق).
- **التقارير:** موظف / قسم / شامل / أرصدة / تعويضات — شهري أو سنوي أو بين تاريخين،
  بتصدير Excel وPDF وطباعة.
- **الإحصائيات:** مؤشرات + رسم بياني للأقسام + توزيع الأنواع + الاتجاه الشهري
  + أكثر 10 موظفين.
- **سجل التدقيق:** كل إضافة وتعديل وحذف وتجاوز، مع بحث وتصفية.
- **النسخ الاحتياطي:** يومي تلقائي + يدوي + استعادة من أي نسخة داخل المجلد.
- **استيراد النسخة القديمة:** ملفات `hosp_leave_*_v3` وملفات JSON القديمة
  تُرحَّل تلقائياً بكل تفاصيلها.

---

## 5) الحمايات المطبّقة

- **ضد XSS:** كل بيانات المستخدم تمر عبر `App.Security.esc()` قبل عرضها.
- **ضد فقدان العمل:** تحذير عند مغادرة النموذج أو إغلاق الصفحة مع تغييرات غير محفوظة.
- **ضد ضياع البيانات:** ثلاث طبقات تخزين + نسخة `.prev` لكل ملف + 30 نسخة احتياطية.
- **ضد فقدان الرصيد:** رصيد الأيام التعويضية مُقيَّد بدل أن يُنسى.

## 6) للمطوّر

### البنية

```
index.html                 الهيكل والتبويبات (بلا onclick مضمّن)
assets/                    مكتبات وخطوط محلية — لا مراجع شبكة إطلاقاً
  js/     tailwind.js · xlsx · html2pdf · chart.umd
  css/    fonts.css · fontawesome.min.css
  fonts/  Cairo + Tajawal (woff2)
  webfonts/
src/css/app.css            الأنماط الخاصة + قواعد الطباعة A4
src/js/constants.js        الثوابت والبيانات الافتراضية
src/js/core/               security · notify · dateUtils · idb · fsa · store · audit
src/js/utils/              exporters · pagination
src/js/modules/            org · leaveTypes · staff · holidays · settings ·
                           conflicts · entry · dashboard · reports · analytics · auditView
src/js/app.js              نقطة الانطلاق والتبويبات وحالة التخزين
tools/browser-test.mjs     مجموعة فحص آلية (131 تأكيداً) في متصفح حقيقي
```

**قاعدتان معماريتان:**
1. **لا وحدات ES** — كروم يحجب `import` على `file://`، لذا كل الوحدات
   سكربتات كلاسيكية داخل IIFE تُسجّل نفسها في `App.*`.
2. **كل الوصول للبيانات عبر `App.Store`** — لا تلمس وحدة واجهة التخزين مباشرة،
   حتى يبقى تبديل التخزين لاحقاً بلا أثر على الواجهة.

### تشغيل الفحوص

```powershell
cd tools
npm install          # مرة واحدة (puppeteer-core فقط)
node browser-test.mjs
```

يفتح النظام في Edge بلا واجهة، ينفّذ 131 تأكيداً (تشغيل، إدخال، تداخل، عطل،
ترحيل بيانات قديمة، XSS، طباعة A4، Excel/PDF حقيقيان، طبقة الملفات والنسخ
الاحتياطية)، ويحفظ لقطات الشاشة في `_screenshots/`.

### الطريق إلى ملف .exe

المعمارية مهيّأة للتحويل لاحقاً **دون إعادة كتابة**:

1. `main.js` + `preload.js` يفتحان `index.html` في نافذة Electron.
2. تُضاف واجهة تخزين ثالثة داخل `App.Store` تعمل عبر IPC
   (البديل يكون SQLite أو نفس ملفات JSON) — **الواجهة لا تتغير**.
3. `webContents.printToPDF` يعطي PDF متجهياً بترقيم صفحات دقيق.
4. `electron-builder` ينتج `Setup.exe` ونسخة محمولة.
5. يوضع مجلد البيانات في `app.getPath('userData')` لا بجانب الملف التنفيذي.

## 7) قيود معروفة

- **ترقيم الصفحات في المطبوع:** كروم لا يدعم `counter(page)` في CSS، لذا سطر
  «الصفحة X من Y» لا يظهر في الطباعة المباشرة. يمكن تفعيل ترقيم المتصفح من
  نافذة الطباعة (خيار «رؤوس الصفحات والتذييلات»)، أو الحصول على ترقيم دقيق
  عبر مسار `.exe` (`printToPDF`).
- **جودة PDF:** التصدير المباشر يحوّل الصفحة إلى صورة. **الطباعة ← «حفظ كـ PDF»
  تعطي جودة أفضل** (نص متجهي قابل للبحث والنسخ). مسار `.exe` يحل هذا نهائياً.
- **Firefox:** لا يدعم الحفظ في مجلد (موقف Mozilla رسمي ضد هذه الواجهة).
- **اسم مشغّل النظام** في سجل التدقيق نصّي بلا كلمة مرور — النظام لمستخدم واحد.
